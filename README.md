# otel-log-wrapper

Zero-config OpenTelemetry setup for Rust services that use `tracing`.

This crate wraps `init-tracing-opentelemetry` with the one-line initialization
style used by `qrt-log-utils`.

## No-Brain Init

```rust
otel_log_wrapper::init!()?;
tracing::info!("service started");
```

The macro derives the service metadata from the calling crate:

- `service.name`: `env!("CARGO_PKG_NAME")`
- `service.version`: `env!("CARGO_PKG_VERSION")`

## Builder Init

Use the builder when you want an explicit service name or config.

```rust
use otel_log_wrapper::LoggerConfig;

LoggerConfig::builder("my-service").init()?;
```

With build metadata from `shadow-rs`:

```rust
shadow_rs::shadow!(build);

otel_log_wrapper::LoggerConfig::builder("my-service")
    .service_version(build::PKG_VERSION)
    .commit_short(build::SHORT_COMMIT)
    .commit_hash(build::COMMIT_HASH)
    .branch(build::BRANCH)
    .build_time(build::BUILD_TIME)
    .init()?;
```

`otel-log-wrapper` does not depend on `shadow-rs`; it only accepts the static
strings generated by the application.

Build metadata is merged into `OTEL_RESOURCE_ATTRIBUTES` before initialization,
so the OpenTelemetry SDK picks it up as resource attributes.

## Recommended Build Metadata Setup

The recommended way to enable commit, branch, and build-time metadata is to
generate static constants in the application and pass them into
`LoggerConfig::builder(...)`.

`shadow-rs` is the documented approach for this crate.

1. Add the dependency in your application:

```toml
[dependencies]
otel-log-wrapper = "0"
shadow-rs = "1"

[build-dependencies]
shadow-rs = "1"
```

2. Add a `build.rs` file:

```rust
fn main() -> shadow_rs::SdResult<()> {
    shadow_rs::new()
}
```

3. Generate the constants and pass them into the logger:

```rust
shadow_rs::shadow!(build);

otel_log_wrapper::LoggerConfig::builder(env!("CARGO_PKG_NAME"))
    .service_version(build::PKG_VERSION)
    .commit_short(build::SHORT_COMMIT)
    .commit_hash(build::COMMIT_HASH)
    .branch(build::BRANCH)
    .build_time(build::BUILD_TIME)
    .init()?;
```

This keeps `otel-log-wrapper` independent from any specific build-metadata
crate while still giving applications a clear recommended integration path.

## Defaults

The default setup:

- sets `OTEL_SERVICE_NAME` from the service name when unset
- sets `OTEL_EXPORTER_OTLP_ENDPOINT` to `http://localhost:4317` when unset
- sets `OTEL_EXPORTER_OTLP_PROTOCOL` to `grpc` when unset
- adds `host.name` to `OTEL_RESOURCE_ATTRIBUTES` when the default `detect-host` feature is enabled
- respects `RUST_LOG`, then `OTEL_LOG_LEVEL`, then falls back to `info`
- uses human-readable stdout logs by default
- initializes a global `tracing-subscriber`
- exports OpenTelemetry traces and metrics
- prints a one-line startup message

Example startup message:

```text
otel-log-wrapper init service=my-service version=0.1.0 commit=abc1234 endpoint=http://localhost:4317 protocol=grpc format=human metrics=true level=my-service=info,hyper=off,my-service=debug
```

## Customization

```rust
use otel_log_wrapper::{LoggerConfig, LoggerFormat};
use tracing::level_filters::LevelFilter;

// Cargo bin/crate names containing a hyphen (e.g. "my-service") are
// normalized to underscores in the actual tracing target ("my_service").
// Always build directive targets with `normalize_target`, not the raw
// Cargo name -- a directive built from the raw hyphenated name silently
// matches nothing and disables logging for that target with no error.
// (A hyphen-free name like "myservice" normalizes to itself, so this is
// always safe to call unconditionally.)
let target = LoggerConfig::normalize_target(env!("CARGO_BIN_NAME"));

LoggerConfig::builder(env!("CARGO_BIN_NAME"))
    .endpoint("http://collector:4317")
    .log_directives(format!("{target}=info,hyper=off,tonic=off,h2=off,reqwest=off"))
    .format(LoggerFormat::Json)
    .default_level(LevelFilter::INFO)
    .startup_message(false)
    .init()?;
```

`log_directives` uses the same directive format as `RUST_LOG`.

If a directive target still contains a hyphen at init time (e.g. someone
passed a raw Cargo name instead of the normalized form), the crate prints
an `otel-log-wrapper warning: ...` line to stderr before installing the
subscriber -- treat that warning as a bug in the caller, not something to
silence.

Merging behavior:

- if `log_directives` is unset, the crate falls back to `RUST_LOG`, then `OTEL_LOG_LEVEL`, then `info`
- if `log_directives` is set and `RUST_LOG` is unset, the crate uses `log_directives`
- if both are set, the crate merges them as `log_directives + "," + RUST_LOG`
- the later `RUST_LOG` directives win on conflicts, so operators can override library defaults globally

The startup line prints the final effective directive string unless you disable it with `.startup_message(false)`.

## Publish Checklist

Before `cargo publish`:

- run `cargo test`
- check for unused direct dependencies and remove them before publishing
- verify the crate still builds with the intended default features

Available formats:

- `LoggerFormat::Human`
- `LoggerFormat::Pretty`
- `LoggerFormat::Full`
- `LoggerFormat::Compact`
- `LoggerFormat::Json`

If you want to own shutdown explicitly instead of storing a global guard:

```rust
let _guard = LoggerConfig::builder("my-service")
    .global_subscriber(false)
    .init_guard()?;
```
